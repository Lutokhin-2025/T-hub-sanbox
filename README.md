В этом проекте я реализовал автоматизированный пайплайн (ETL) для работы с данными о международных аэропортах. Главная задача была — сделать систему, которая сама собирает информацию, сохраняет её и выдает красивый результат без ручного вмешательства. Весь стек приложения упакован в Docker, поэтому его можно запустить на любой машине одной командой.

Что именно было сделано:

1. Сбор данных через API Я настроил получение информации из публичного JSON-источника с помощью библиотеки requests. Программа автоматически скачивает данные о более чем 6700 аэропортах. Использование метода .json() позволило сразу преобразовать ответ сервера в удобный для Python список словарей, а обработка исключений гарантирует, что скрипт не упадет при проблемах с сетью.

2. Создание базы данных и хранение Для хранения я развернул PostgreSQL внутри отдельного Docker-контейнера. Чтобы обеспечить надежность, я добавил healthcheck — моя программа не начнет работу, пока база данных не будет полностью готова. Для заполнения таблицы использовался SQLAlchemy: я описал схему данных, и ORM сама создала таблицу, в которую затем были загружены все 6700+ записей. Это позволило избежать написания сложных SQL-запросов вручную и обеспечило целостность данных.

3. Нормализация и обработка (Pandas) С помощью Pandas я привел все столбцы к нужным типам данных (например, широту и долготу к float, а высоту над уровнем моря к int). Это критически важный этап, который очищает данные перед сохранением и защищает базу от ошибок вставки.

4. Генерация визуального отчета Вместо того чтобы просто вывести текст в консоль, я реализовал генерацию наглядного отчета. Библиотека matplotlib берет из базы первые 20 аэропортов (отсортированных по названию) и рисует из них аккуратную таблицу. Результат сохраняется как готовое изображение airports.png в папку reports.

5. Оркестрация через Docker Compose Чтобы проект работал из коробки, я связал Python-приложение и базу данных с помощью Docker Compose. Они работают в одной изолированной сети и общаются по имени сервиса (db). Теперь для запуска всей системы — от поднятия базы до генерации картинки — достаточно выполнить docker-compose up --build.

Что получилось в итоге

У меня вышел готовый, переносимый инструмент для обработки данных. Это отличный фундамент: если завтра мне понадобятся не аэропорты, а, например, курсы валют, я просто поменяю ссылку в коде и структуру таблицы, а вся логика ETL останется прежней. Проект демонстрирует полный цикл разработки: от работы с внешним API до создания готового визуального продукта.
